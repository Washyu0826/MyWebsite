## 1. Rules MCP Server

**成果（`outcome_zh` / `outcome_en`）** — 任一項有數字的都好：

- 上線或轉換了多少條規則
- 一條規則從自然語言到可執行，前後各要多久
- 生成的 JSON 一次通過驗證的比例
- 團隊少做了哪一段人工工作

沒有數字的話，寫「這條規則現在誰都能改，不用等工程師」這種質性的改變也有說服力，但要具體。

## 2. 繁中健康問答系統

**成果** — 可用的角度：

- 回答的準確率或人工評分，以及怎麼評的
- 回應時間
- 相較於原本「搜尋加翻文章」節省了多少步驟或時間
- 有沒有上線、給誰用、用量如何

## 3. 帕金森氏症早期偵測

**架構（`body_zh` / `body_en`）** — 這是最值得寫的一塊，也是最能展現研究深度的地方：

- 用了哪幾種模態？（影像、語音、動作、量表、感測器？）
- 各模態怎麼融合？早期融合、晚期融合，還是注意力機制？
- 模型架構大致是什麼？
- 資料規模與來源，以及倫理審查的處理方式（能寫多少寫多少）
- 最難的技術問題是什麼，怎麼解決的

**成果** — AUC、敏感度、特異度這類指標，以及和單一模態或既有方法的比較。如果論文還在進行中，寫「目前進度」也可以。

## 4. 台北租屋市場

**架構** — 資料從哪來（591？實價登錄？自己爬？）、清理時遇到什麼問題、做了哪些特徵、用了哪個模型、怎麼驗證。

**成果** — 預測誤差（MAE、RMSE 之類）、資料筆數、有沒有做成可以查詢的介面。

## 5. Infintas AIoT 語音控制助理

這個目前只有一句話，需要最多資訊：

- **問題**：想解決什麼？為什麼需要語音控制？使用情境是什麼？
- **解法**：控制哪些裝置？語音辨識用什麼？意圖理解怎麼做？
- **架構**：硬體與軟體怎麼分工？離線還是雲端？
- **團隊**：幾個人？你身為 CTO 實際做了什麼、決定了什麼？
- **成果**：做到什麼程度？有沒有實際 demo、得獎、或使用者回饋？

## 六個都需要的：封面與截圖

現在六個專案都沒有 `cover_url`，列表頁因此沒有縮圖，Open Graph 分享出去也沒有圖。

- **封面圖**：一個專案一張，用 `/admin/projects` 編輯頁的「上傳並填入網址」。系統會自動轉 WebP、限制尺寸、移除 EXIF（含拍攝地點），並產生模糊佔位圖。
- **截圖或架構圖**：在編輯頁下方的媒體區塊新增，可拖拉排序。畫面紀錄比文字更能說明一個系統長什麼樣。

不能公開畫面的專案（國泰、H2U 都可能有這個問題），用一張自己畫的架構示意圖代替即可，不要放真實的後台截圖。

## 量化成果欄位

除了 `outcome_*` 的敘述，每個專案還可以加幾個「數字加標籤」的量化成果，會顯示成醒目的欄位。在 `/admin/projects` 編輯頁的「量化成果」區塊新增，例如：

| value | label_zh | label_en |
| --- | --- | --- |
| `P95 120ms` | 回應延遲 | Response latency |
| `92%` | 一次驗證通過率 | First-pass validation |
| `1,000+` | 轉換規則數 | Rules converted |
